# LumaRig Studio v0.3 Functional Core

v0.3 converts the existing interface into one authoritative show-control runtime.

## Rule

No decorative controls. A visible control either operates a real subsystem, reports unavailable hardware/provider state, or is disabled with an explicit reason.

## Runtime

One master transport owns song time. Audio is the clock authority. Section transitions are derived from transport position and dispatch cues to MIDI, video, NDI, and lighting.

## Work order

1. Native project persistence, autosave, recovery, media manifest and relink.
2. Multiformat audio import, track lifecycle, buses and output routing.
3. Real 12-pad sampler.
4. Master section scheduler and cue dispatcher.
5. Video compositor and fullscreen/external display output.
6. NDI sender provider. ProPresenter receives the named Studio program feed.
7. MIDI device/output runtime.
8. LumaRig provider with heartbeat, arm state, scenes, FX, blackout and reconnect.
9. Performance Mode, failure isolation and recovery.
10. End-to-end tests and release packaging.

## Video provider boundary

The compositor renders once. Display and NDI are sinks. NDI must not own playback state or timing.

## LumaRig provider boundary

Studio sends semantic commands (scene, FX, blackout, group intensity/color) rather than DMX channels. LumaRig remains the lighting authority.

## Failure policy

Loss of NDI, MIDI, video display, or LumaRig must never stop audio. Each provider reports degraded state and retries independently.
